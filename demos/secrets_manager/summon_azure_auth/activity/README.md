# Hardcoded Secret Remediation Activity

This activity creates per-student workspaces under `/opt/labs/studentN/hardcoded-secret-remediation`.

It assumes the platform setup is already complete:

- Azure SQL database exists.
- Student SQL users and passwords exist.
- CyberArk safes and accounts exist.
- `authn-azure` is configured.
- The Azure workload can read the student safes.
- `conjur_authn_azure.env` has already been generated by the parent demo setup.

## What Students Do

Students compare a hardcoded database query script with a secured version that uses Summon and CyberArk Secrets Manager.

The query remains inline in the scripts. Only connection secrets are removed from code.

## Generate Student Workspaces

From the parent demo directory:

```bash
cd demos/secrets_manager/summon_azure_auth
```

Set the required activity inputs:

```bash
export STUDENT_COUNT=30
export SQL_SERVER="myserver.database.windows.net"
export SQL_DATABASE="trainingdb"
export SQL_QUERY="SELECT TOP 5 * FROM dbo.ExampleTable"
```

Set credential and CyberArk naming templates:

```bash
export DB_USERNAME_TEMPLATE="__STUDENT___user"
export DB_PASSWORD_TEMPLATE="replace-with-lab-password-pattern"
export SAFE_NAME_TEMPLATE="${LAB_ID}-__STUDENT__-sql"
export ACCOUNT_NAME_TEMPLATE="azure-sql-__STUDENT__"
```

Then run:

```bash
bash activity/setup_activity.sh
```

## Per-Student Overrides

If credentials or CyberArk names do not follow a simple pattern, set numbered overrides before running setup:

```bash
export DB_USERNAME_1="student1_user"
export DB_PASSWORD_1="student1-password"
export SAFE_NAME_1="${LAB_ID}-student1-sql"
export ACCOUNT_NAME_1="azure-sql-student1"
```

Supported override prefixes:

- `SQL_SERVER_N`
- `SQL_DATABASE_N`
- `DB_USERNAME_N`
- `DB_PASSWORD_N`
- `SAFE_NAME_N`
- `ACCOUNT_NAME_N`

Where `N` is the numeric student index, for example `1`, `2`, or `30`.

## Student Command

Each student runs:

```bash
cd /opt/labs/student1/hardcoded-secret-remediation
./query_db_hardcoded.sh
./run_secured_query.sh
```
