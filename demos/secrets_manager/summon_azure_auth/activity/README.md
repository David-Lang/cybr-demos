# Hardcoded Secret Remediation Activity

Generates the per-student workspace under `/opt/labs/studentN/hardcoded-secret-remediation`
for the Summon Azure Auth workshop. The database is a **VM-local PostgreSQL** (stood
up by `db_setup.sh`); the scripts use `psql`.

It assumes the deployment enablement is already done (normally by `setup_vm.sh`):

- Summon + the `summon-conjur` provider are installed.
- The tenant PostgreSQL platform is validated available.
- `authn-azure` + the workload identity are configured.
- `conjur_authn_azure.env` has been generated by the parent demo setup.
- The local Postgres container is running with the initial credential.

The safe is **not** pre-created — the student creates it and vaults the credential
in the activity (that is the lesson).

## What Students Do

Compare a hardcoded query script with a secured version that fetches the DB
credential at runtime via Summon + the VM's Azure managed identity, then vault and
rotate it: **expose → vault → secure → rotate**. The query stays inline; only
credential handling changes.

## Generate The Workspace

From the parent demo directory:

```bash
cd demos/secrets_manager/summon_azure_auth
vi activity/inputs.env       # optional — sensible defaults are provided
bash activity/setup_activity.sh
```

`activity/inputs.env` (defaults match `db_setup.sh`, so usually no edits needed):

```env
# Local Postgres the scripts connect to
DB_HOST="localhost"
DB_PORT="5432"
DB_NAME="trainingdb"

# Initial credential the hardcoded script exposes and the student vaults
DB_USERNAME="appuser"
DB_PASSWORD="InitialSecret1!"

# Postgres query rendered into the scripts
SQL_QUERY="SELECT * FROM example_table ORDER BY id LIMIT 5;"

# CyberArk targets baked into secrets.yml (student vaults with these exact names)
SAFE_NAME="<defaults to the VM name>"
ACCOUNT_NAME="postgres-appuser"
ROTATION_ADDRESS="<connector-reachable VM address; for SRS rotation>"

# One VM per student
STUDENT_COUNT="1"
```

## Student Commands

Each student, in their workspace:

```bash
cd /opt/labs/student1/hardcoded-secret-remediation
./query_db_hardcoded.sh     # expose: password is inline in the script
# vault the credential in CyberArk (see student_guide.md), then:
./run_secured_query.sh      # secure: same result, no secret in the script
```
