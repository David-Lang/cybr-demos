# SPIFFE / SPIRE → CyberArk Conjur Cloud (`authn-jwt`)

Stand up a local Kubernetes cluster running SPIRE, federate its JWT-SVIDs into
CyberArk Conjur Cloud's `authn-jwt` authenticator, and demo an AI agent
retrieving a vaulted secret with zero credentials in its pod spec.

CyberArk doc this implements:
[Authenticate AI agents with JWT SVIDs (SPIFFE)](https://docs.cyberark.com/secrets-manager-saas/latest/en/content/operations/authn/authenticate-ai-spiffe.htm).

## Quick Start

```bash
cd $CYBR_DEMOS_PATH/demos/secure_ai_agents/spiffe_conjur

# 1. Configure (defaults derived from $LAB_ID; setup.sh auto-seeds from .example on first run)
cp setup/vars.env.example setup/vars.env   # or just run setup.sh — it copies for you
vi setup/vars.env

# 2. Set up — runs four stages: spire, workloads, oidc (cloudflared), conjur
./setup.sh

# 3. Run the interactive 12-min demo
./demo.sh

# 4. Tear down the local cluster + remove Conjur policies/secret
./cleanup.sh
```

## What This Demo Proves

| | BEFORE (`vulnerable-agent`) | AFTER (`attested-agent`) |
|---|---|---|
| Where the credential lives | etcd + pod spec + container env | retrieved on demand via SPIFFE + Conjur Cloud |
| Who can read it | anyone with `get/exec` on the namespace | only the workload SPIRE attests |
| Rotation | edit Secret + restart consumers | `conjur variable set ...`, no app restart |
| Revocation | redeploy without the Secret reference | delete one `ClusterSPIFFEID` |
| Audit | none | every authn + every secret read logged in Conjur |

## Stage Scripts (also runnable individually)

| Stage | Script | Purpose |
|---|---|---|
| 1 | `setup/spire/setup.sh` | minikube + helm install spire + ClusterSPIFFEID |
| 2 | `setup/workloads/setup.sh` | apply BEFORE pod + render+apply AFTER pod |
| 3 | `setup/oidc/setup.sh` | start cloudflared tunnel + helm-upgrade SPIRE jwtIssuer |
| 4 | `setup/conjur/setup.sh` | load 4 Conjur policies + set authn variables + enable + seed secret |
